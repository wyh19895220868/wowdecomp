# 项目架构与开发入口

本文根据 2026-10-25 本地 README、CMake 配置及源码目录整理。用于定位功能与约束开发范围；不代表已通过本地编译、联机或性能验收。

## 一、工作区与目标

- `E:\wowdecomp\wowdecomp`：新客户端，主要开发及 Git 提交目录。
- `E:\wowdecomp\wowdecomp-main`：旧客户端，作为历史实现和差异参考。两者是独立仓库，不共享修改或构建缓存。
- `E:\AA\azerothcore-wotlk-master`：用户的 AzerothCore WotLK 服务端。客户端所有定制功能与通讯均围绕它实现。

新客户端远程仓库：<https://github.com/wyh19895220868/wowdecomp>。工作区容器 `E:\wowdecomp` 的 `AGENTS.md` 负责导航，规则正文及本文由新客户端仓库跟踪。每项修改使用该仓库中的功能子分支，按功能块提交；旧客户端目录不是 Git 子分支。

客户端基于 WoW 3.3.5a（12340）重建，使用 C++17，目标平台为 Windows。x64 为主要运行架构，Win32 用于兼容及原版布局核对。游戏数据由对应版本客户端提供，不包含在源码中。

## 二、客户端模块

- `WoW/Source/Win64/WinMain.cpp`：x64 平台入口；另有 Win32 平台实现。`WoW/Source/CMakeLists.txt` 组装 `Wow` 可执行目标。
- `WoW/Source/Glue/`：登录、角色选择和加载等进入世界前的界面流程。
- `WoW/Source/WowServices/`：登录及服务器连接相关实现，重点入口包括 `GruntLogin.cpp`、`Grunt.cpp`、`SRP6_Client.cpp`、`RealmConnection.cpp`；同时存在 Battlenet 登录实现，实际选用路径应按配置和调用链核实。
- `WoW/Source/Net/NetClient/`：客户端网络处理入口，`NetClient.cpp` 包含认证挑战、连接和消息处理分支。
- `WoW/Source/WowSvcs/WowSvcsClient/`：客户端服务整合、账号数据、好友及下载相关功能，入口可从 `ClientServices.cpp` 定位。
- `WoW/Source/Object/`、`ObjectAlloc/`、`ObjectMgrClient/`：对象表示、分配及客户端对象管理。
- `WoW/Source/WorldClient/`、`Game/`、`Magic/`：世界、游戏流程及法术相关模块；具体功能必须追踪实际调用关系。
- `WoW/Source/Ui/`、`UIUtil/`：游戏 UI 及辅助逻辑；`DB/` 和 `WoW/Common/` 提供客户端数据与公共代码。
- `Engine/Source/Frame/`、`FrameXML/`、`FrameScript/`、`lua-5.1/`：界面框架、XML、脚本绑定及 Lua 运行环境。
- `Engine/Source/Gx/`、`Gxu/`、`Model2/`、`ShaderEffect/`、`FFX/`、`Scrn/`：图形设备、模型、着色及画面效果。
- `Engine/Source/Storm/`、`Base/`、`BlizzardCore/`、`Os/`、`Event/`、`SoundEngine/`：资源与基础设施、系统、事件和音频。
- `ThirdParty/`：第三方依赖；保持既有集成方式，避免为单功能修复升级整个依赖栈。
- `Tools/WowClient/`：带可选崩溃日志的客户端目标；`Tools/XvidDecoder/`：x64 视频解码 DLL。

以上是源码定位索引，不能仅凭目录名推断某个具体包或功能的完整调用链。

## 三、服务端配套与通讯定位

典型排查顺序：界面/脚本事件 → 客户端业务处理 → 消息编码及连接 → 服务端协议分发 → 业务处理 → 响应 → 客户端状态和界面更新。每项功能都需在源码中确认实际链路。

服务端路径均相对于 `E:\AA\azerothcore-wotlk-master`：

- `src/server/apps/authserver/`：认证服务入口及认证相关网络处理。
- `src/server/apps/worldserver/`：世界服务入口。
- `src/server/game/Server/WorldSocket.cpp`：世界连接处理。
- `src/server/game/Server/Protocol/Opcodes.h`、`Opcodes.cpp`：操作码及分发定义。
- `src/server/game/Server/WorldSession.h`、`WorldSession.cpp`：会话；具体处理逻辑还需定位相关 Handler 实现。
- `src/server/scripts/`、`modules/`：玩法脚本和自定义模块，应按本次功能进一步定位。

通讯变更需记录请求/响应、字段格式、状态和失败处理，并对照两端实现。保持 12340 协议兼容；客户端升级为 x64 不意味着协议字段变为 64 位。身份、权限、资源扣除等业务校验由服务端执行。

先读取服务端 `AGENTS.md`；其当前规则要求明确请求后才配置或构建服务端。涉及额外功能的配套修改必须先说明并取得用户确认。

## 四、构建与运行入口

在新客户端源码根目录执行。要求 Windows、VS 2022 C++ 工具链及 Windows SDK；使用与工具链兼容的 CMake，实际最低能力以 CMakeLists 使用的命令为准。

```powershell
cmake -S . -B build/x64 -G "Visual Studio 17 2022" -A x64
cmake --build build/x64 --config Release --target WowClient --parallel
cmake --build build/x64 --config Release --target XvidDecoder --parallel
```

上述命令源自项目配置，本文编写时未执行构建。必须使用独立构建目录，禁止源内构建；已有缓存需确认生成器、架构和源码路径一致。

- `WowClient` 默认输出 `bin/Win/WowClient64.exe`，启用崩溃日志时产生 `WowClient_crash.log`。
- `Wow` 输出 `bin/Win/Wow64.exe`；Win32 对应 `WowClient32.exe` / `Wow32.exe`。
- `XvidDecoder` 输出 `bin/Win/XvidDecoder.dll`，运行准备需检查该依赖。
- `BuildWaystone.bat` 使用 VS 2022 和 Ninja，构建 `Wow`、`XvidDecoder` 并打包；其实际构建类型为 `RelWithDebInfo`，目录名为 `out/build/x64-Release`。仅写文档时无需运行。
- Win32 构建额外需要 NASM 和原版 `DivxDecoder.dll`，详见 README。
- `GameVersion.h` 保存游戏版本标识；构建生成的 `WaystoneVersion.h` 来自 Git 信息，不应手工编辑生成文件。
- 运行需要 `bin/Win/Data/` 下的 3.3.5a 数据，以及指向用户服务端的实际 realmlist 配置；本文不假定部署地址、账号或服务已启动。

## 五、功能修改与验收

1. 读取 `AGENTS.md`，确认当前功能、源码仓库、用户改动及子分支。
2. 定位客户端调用链；通讯功能同时只读核对服务端实现，旧客户端按需参考。
3. 若必须连带修改其他功能，先列出原因、方案和影响，等待用户确认。
4. 完成本功能最小修复，复查点击、每帧更新、资源加载、网络回调的优化空间。
5. 按改动执行适当验证，关注首次和反复操作的耗时、帧时间、重复请求与资源增长；避免主线程等待和无效重复工作。
6. 按功能块审查并提交本地 Git，报告分支、哈希、修改范围、验证结论及待验收事项。

编译通过、能启动、能联机、功能正确和操作流畅是不同层级的证据，必须分别如实报告。当前文档只确认目录及配置结构，不声明运行质量。
